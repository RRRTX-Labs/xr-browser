## P7 — command registry + four views (consuming the frozen `command-descriptor-v1`)

P7 is the first real consumer of the P5-frozen `command-descriptor-v1` contract
and the P6 one-brain policy. It **implements to the frozen descriptor and never
redefines it.** New command surfaces do not amend the descriptor schema; they
extend it through four sanctioned extension points, each a *value*, not a
*schema* change:

| Extension point | How a new surface adds a command | Gate that bites |
|---|---|---|
| `descriptor.handler` | a new `action.<group>.<verb>` — dispatch in `commands_host` only, never TS | id whitelist (an unknown id never reaches a handler) |
| `registry.predicate_id` | a new availability-predicate id (e.g. `settings.<x>-ready`), read from the P6 resolver snapshot | availability-predicate contract (`host_protocol.md`) |
| `registry.group` / `registry.keywords` | a new menu group + palette keywords | menu-model golden (`tools/menu_model_check.py`) |
| `descriptor.attention_tier` | promote/demote within the Tier-1 ≤ 9 budget | registry `kMaxTier1=9` (a 10th tier-1 is rejected at load) |

A placeholder command (e.g. `tor.open`) registers **disabled via its availability
predicate with a reason** — never absent, never a "coming soon" rail (§10). New
*landed* surfaces (settings sections in P8, panel tabs in P13) are gated by the
§10 coverage ratchet: `docs/contracts/coverage-allowlist.yaml` pre-declares each
future surface with its covering command, which must stay registered; a surface
that lands in the tree without a registered command FAILS
(`tools/coverage_check.py`).

The new `command-host-protocol v1` contract (table above) is the data contract the
four views consume. It is frozen by the 31-case C++⇄Python byte-parity (the
Python reference fake `fakes/commands.py` is the parity reference); amending it
is an RFC through this same registry (P6-T5 pattern), not an in-place edit.

### `xr_command_registry_v1` flag — EXPIRY (2 of 2)

(1/2 is the `default:` + `EXPIRY (1/2)` note in `build/gn/argsets/flags.yaml`.)

- **Kept until P13** (the XR Panel lands). Until then the flag is the kill-switch
  for the entire P7 surface: `xr_command_registry_v1 = false` ⇒ stock chrome,
  empty registry, and all four views render nothing.
- **Retirement:** at P13, once the XR Panel is the primary command surface, the
  flag is retired (removed from `flags.yaml` + `xr_common.gni`) only after the
  registry is the default. Retirement is itself a post-freeze registry change (a
  row above + an RFC), so the kill-switch cannot be silently dropped.
