# policy-change-event v1

**Status:** FROZEN surface consumer (P6-T5). Schema:
`policy-change-event-v1.schema.json`. Generator: `xr-core/policy/core/events.cc`
(pure: old policy + new policy + context in, canonical JSON out). Golden
strings are unit-tested in xr-core (`policy/tests/test_events.cc`).

## What it is

The dial strip's data contract (the UX surface itself is P8): a machine-
readable, human-summarized account of **what changed** when a site's
effective policy changes, with an **Undo affordance** when the change is
user-actionable.

## Shape

```json
{
  "event": "policy_changed",
  "contract_version": 1,
  "identity": "xr:00000000-0000-4000-8000-000000000001",
  "site": "example.com",
  "previous_trust": "kStandard",
  "new_trust": "kFortress",
  "deltas": [
    {"path": "cosmetic.hide_cosmetic", "from": "false", "to": "true",
     "change": "on", "human": "hide_cosmetic on"},
    {"path": "permissions.camera", "from": "kAsk", "to": "kDeny",
     "change": "blocked", "human": "camera now blocked"},
    {"path": "egress.route", "from": "kDirect", "to": "kTor",
     "change": "rerouted", "human": "route now tor"},
    {"path": "process_policy.dedicated_process", "from": "false", "to": "true",
     "change": "on", "human": "stricter isolation"}
  ],
  "summary": "hide_cosmetic on · block_scriptlets on · geolocation now blocked · camera now blocked · microphone now blocked · notifications now blocked · egress.block_third_party on · route now tor · stricter fingerprint protection · storage now scope kFortressPartition · stricter isolation · letterbox isolation on",
  "undo": true
}
```

The full canonical golden (all 12 deltas for a Standard→Fortress switch on a
persistent standard identity) is `docs/contracts/tests/golden-policy-change-event.json`
— generated by the C++ generator and byte-verified against it.

## Laws

- **Concrete deltas, no scores.** Every delta names a field, its previous and
  next value, a classification (`blocked` / `unblocked` / `ask-every-time` /
  `on` / `off` / `rerouted` / tier names), and human copy ("camera now
  blocked", "route now tor", "stricter fingerprint protection"). There is NO
  score, risk number, or grade anywhere — that vocabulary is banned
  (§10 vocab law) and the absence is lint-tested.
- **No auto-reload.** The event describes a change; it never instructs a
  reload. The field is absent BY CONTRACT (absence-lint fixture proves it);
  a future auto-reload behavior would be an RFC, not a field addition.
- **Undo is an affordance, not a promise.** `undo: true` on user-actionable
  changes (in-flow dial moves, expiring exceptions); `false` for enterprise-
  enforced changes (managed policy cannot be undone from the strip).
- **Deterministic.** Same (old, new) pair ⇒ byte-identical event. Delta
  order follows the canonical field order of `EffectivePolicy` v1.

## Consumers

- P8 dial strip (renders summary + Undo affordance)
- Activity ledger correlation (P13 isolation card "why" rows)
