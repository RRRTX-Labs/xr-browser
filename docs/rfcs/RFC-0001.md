# RFC-0001: amend the xr.mojom freeze to add the Cosmetic interface

- **Status:** DRAFT  (APPROVED is a human act — an agent never self-approves;
  this file stays DRAFT until a human sets `status: APPROVED`, per
  `docs/contracts/contract-amendment-rfc.md` step 2)
- **Contract(s):** xr-core `mojom/` freeze surface (§1.11 LIST) — adds a NEW
  unit, `cosmetic.mojom`; amends the `mojom/BUILD.gn` source list.
- **Author:** P12-CLOSE coding agent (draft)  **Date:** 2026-09-19

## Summary

Add `xr-core/mojom/cosmetic.mojom` (interface `Cosmetic`) to the frozen
`xr.mojom` surface: the renderer requests the compiled cosmetic key-set for a
frame's own `(site, identity-trust)` scope at document-start, and the
network-service blob cache stores/evicts compiled blobs and identity
partitions. Sizes are pinned from the live core headers as `// budget:`
comments.

## Motivation

Plan §8 (P12-T2) requires the renderer-side cosmetic feature to obtain its
compiled rules "via mojom" and the network service to keep a "per-page rule
blob cache … identity-aware keys". Today the core exists
(`renderer/cosmetic/core/`) with a stdio TEST protocol
(`renderer/cosmetic/host_protocol.md`) but no browser boundary. Without this
file the browser seam the plan's Blink patch consumes has no contract, and
the fuzz coverage law (`tools/tests/test_mojom_coverage.py`) would have no
ninth interface to hold the generator honest against.

## Proposed change

- NEW `xr-core/mojom/cosmetic.mojom`: `interface Cosmetic` with
  `GetCompiledRuleSet`, `CacheCompiledBlob`, `EvictCompiledBlob`,
  `EvictIdentityPartition`, `CacheOccupancyBytes`; typed enums/structs only
  (R5: no stringly error field); `CosmeticScope.embedder_site` documented as
  REFUSED non-empty; `// budget:` comments cite `core/keyset.h` /
  `core/scope_key.h` limits verbatim.
- `xr-core/mojom/BUILD.gn`: add `"cosmetic.mojom"` to the `mojom("mojom")`
  source list (11 → 12 files).
- Versioning: `const int32 kContractVersion = 1;` in the new file (its own
  freeze stamp, like every sibling file).

## Migration

Forward-only. No existing consumer reads `cosmetic.mojom`; the bindings
compile remains farm-gated (HG-9/HG-27) like the other eleven files. The
Python fake `xr-core/fakes/cosmetic.py` and the stdio host already implement
this exact method set (P12-T1), and the parity corpus
`tools/parity/corpus-cosmetic.json` carries the cases — no new fake work is
implied by this file.

## Backward compatibility

Existing frozen interfaces are untouched. Consumers of `mojom/` that
enumerate files (the lint, the coverage test) see one more file; BUILD.gn
sources remain an additive list.

## Security review

Narrow surface; typed errors only (`CosmeticError` union over `CosmeticResult`);
no generic exec (R4 banned names absent); the only cross-partition-sounding
input (`embedder_site`) is refused, not ignored; the cache key reuses the
`(identity, site, trust)` seam already decided in `policy/core/cache.h` —
documented in `docs/renderer/blob-cache.md` so the two cannot drift.
